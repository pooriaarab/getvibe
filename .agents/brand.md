# Brand Context

## Identity

`getvibe.dev` is the catalog for The Vibe Suite.
It helps developers choose a small companion for an agent coding workflow.
The catalog is a static website, not a product API or account service.

## Audience

The primary audience uses agentic coding CLIs such as Claude Code, Codex, and Gemini.
Visitors want a quick explanation, an exact install command, and a source link.

## Promise

Present the suite as local-first companions: your machine, your keys.
Describe each tool's actual network and credential behavior on its own page.
Keep the catalog free of accounts, billing, checkout, and fabricated plans.

## Voice

- Lead with the tool and its concrete job.
- Use short, direct sentences.
- Show the exact command near the description.
- Prefer evidence over broad privacy or performance claims.
- Avoid hype, testimonials, metrics, and SaaS sales language.

## Naming

- Write `getvibe.dev` in lowercase.
- Write `The Vibe Suite` with those capitals.
- Keep product names lowercase.
- Preserve package differences: `viberadio-fm` and `vibeshare-live`.
- Link `vibedate` to the `pooriaarab/vibedating` repository.

## Mark

The mark is the inline pulse path used in `index.html` and `favicon.svg`.
Use round caps and joins.
Render it in signal amber on the dark canvas.
Pair it with the lowercase `getvibe.dev` wordmark.

## Claims

Current repository evidence supports these claims:

- The site catalogs ten companion tools.
- Each tool has one visible install command.
- The catalog has no account, paid plan, or checkout.
- The site uses system fonts and self-contained static assets.

Verify every product claim against its owning repository before publication.

## Assets

- Site structure and copy: `index.html` and product directories.
- Visual source: `styles.css`.
- Pulse mark: `favicon.svg`.
- Social image: `og-image.png`.
- Product videos: `videos/`.
